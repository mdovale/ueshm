# M1 — docs, shared bulk, tool-driven frames, windowed HUD

Handoff for the rest of the milestone. Steps 1 and 2 are done. The binary speaks version 2: the header carries the bulk halves, and `DUMP` writes the engine half. `STEP` is reserved and not dispatched. Sync and the window are not built.

The tree speaks version 2. `uectl` creates a 16 MiB region, launches `UnrealEditor-Cmd` with `-game -nullrhi`, and the plugin opens that region. One command ring, one reply ring, and a bulk span split into a tool half and an engine half. `DUMP` writes the engine half. Five orders are handled: `PING`, `CONSOLE`, `SPAWN`, `DUMP`, `QUIT`. `STEP` is reserved. Both sides poll. The engine clock is the wall clock. `demo` is the engine acceptance run; CI runs only the five C++ tests.

M1 keeps that run working. Sync and the window are opt-in.

## Verdict

Steps 1 and 2 are ordinary. Do them first. Step 2 changes the region layout, and steps 3 and 4 should be written against that layout rather than against version 1.

Steps 3 and 4 are feasible on UE 5.8.4. They are one design, not two. A tool-driven frame that blocks inside the engine loop will deadlock the tool, and it will also freeze the window step 4 is supposed to show. The timestep has to return every loop. The tool publishes a step; the engine ticks once with that delta; the window keeps presenting on the loops where no step is waiting.

Do not drive this with `FApp::UseFixedTimeStep` alone. That flag still advances on the wall clock. The engine hook that exists for an external clock is `UEngineCustomTimeStep` (`Engine/Source/Runtime/Engine/Classes/Engine/EngineCustomTimeStep.h`). Genlock uses it by sleeping inside `UpdateTimeStep`. This milestone must not.

## What the engine loop actually does

Confirmed in this machine's 5.8.4 tree.

`UEngineCustomTimeStep::UpdateTimeStep` returns `bool`. `false` means the subclass already wrote `FApp` current time and delta, and `UEngine::UpdateTimeAndHandleMaxTickRate` must skip its own clock math. The frame is not skipped. `LaunchEngineLoop.cpp` then calls `GEngine->Tick`, redraws the viewport, ticks `FTSTicker`, and broadcasts `FCoreDelegates::OnEndFrame`.

Call order on every loop iteration:

1. `UpdateTimeAndHandleMaxTickRate` → `UpdateTimeStep`. This is before the world tick. Game thread.
2. `UGameEngine::Tick` → world tick, then `RedrawViewports` (which is where `AHUD::DrawHUD` runs).
3. `FTSTicker::GetCoreTicker().Tick`. This is where the plugin drains commands today, so a command popped now affects the *next* world tick.
4. `FCoreDelegates::OnEndFrame`.

`t.IdleWhenNotForeground` defaults to `0` (`ConsoleManager.cpp`). If it is `1`, an unfocused `-game` process sets idle mode *after* the custom timestep returns, and `UGameEngine::Tick` then skips the world tick and the redraw. A step consumed in `UpdateTimeStep` would not simulate, and an ack on `OnEndFrame` would lie. Pin the cvar to `0` from the project so that cannot happen. Default is already `0`; the pin is there so a later config change does not break sync.

`-nullrhi` skips real rendering. `DrawHUD` does not produce a visible overlay in that mode. A window requires leaving `-nullrhi` off. `UnrealEditor-Cmd` is still the binary to launch. `Engine/Binaries/Mac/UnrealEditor.app` exists if the Cmd binary does not come forward or does not take focus; try Cmd first.

## Protocol version 2

The byte layout, the orders, and the fences are `docs/protocol.md`. That file wins if this handoff disagrees with it. Summary of what it requires:

Bump `kVersion` from 1 to 2. A version mismatch already leaves `state` at 0, and the tool hits the ready timeout. Both sides ship together. Do not keep a version-1 reader. The header stays 128 bytes. Offsets 0 through 44 stay put. New fields occupy the pad at offset 48: `flags`, `frame`, the last-command mirror, and the two bulk halves. `flags` bit 0 is sync. The tool writes only the low half. The engine writes only the high half. `DUMP` moves to `ue_bulk_off`. `STEP` is type 6, `f32 dt`. `STEP_ACK` is type 105, pushed from `OnEndFrame` after the world tick, with `u32 frame` and `f32 speed`. `dt <= 0` or `dt > 1` is `ERR`.

## Step 2 — both sides write bulk

Done. `kVersion` is 2. The halves do not overlap. `DUMP` and the spawn cap use the engine half. `demo` still checks `x = i * 100` and does not write the tool half. `kStep` and `kStepAck` are reserved. ## Step 3 — tool-driven timestep

Sync is off unless `flags` bit 0 is set. `uectl step` sets it. `ping`, `exec`, `demo`, and `launch` do not, unless `--sync` is also passed. Free-running mode keeps today's ticker drain, today's timeouts, and today's `demo` exit checks.

In sync mode the plugin installs a `UEngineCustomTimeStep` on the first tick where `magic` and `version` match, via `UEngine::SetCustomTimeStep`. Do not set `CustomTimeStepClassName` in ini, or free-running sessions would take the same clock. Subclass it in the plugin. `Engine` is already a module dependency. `TimeManagement` is not needed.

`UpdateTimeStep` in sync mode:

- Runs on the game thread. It is the only consumer of the command ring. The ticker must not pop in this mode. The ticker still bumps `ue_heartbeat` and still sets `state` to `ue_ready`.
- Drains up to 64 commands, same cap as today. Stops early if the next record is `STEP` and 64 have not been consumed yet: commands before `STEP` are applied, `STEP` is consumed, anything after `STEP` stays for the next loop.
- On `STEP` with an accepted `dt`: set `FApp` current time and delta to that `dt`, remember that an ack is owed, return `false`.
- With no `STEP`: sleep in 2 ms slices for up to one 30 Hz period, rechecking the ring between slices. Then set delta to 0, pause the game world for this tick, return `false`. A zero delta plus pause means idle loops present and run the HUD, and they do not integrate the spawned actors. Pause through the world, not through `t.IdleWhenNotForeground`.
- On `QUIT`: push `ACK`, `RequestExit`, return `false`.

Seeing `STEP` cancels the rest of the idle sleep. The tool's reply timeout is 10 s, so a 2 ms slice is invisible.

On the matching `OnEndFrame`, and only if a `STEP` was consumed this loop: integrate actors, release-store `frame`, push `STEP_ACK`. Integration is plugin code, not Chaos. Each spawned actor moves by `speed * dt` on X. `speed` is the `f32` at `tool_bulk_off`. If that value is 0, actors stay put. Do this only for a consumed `STEP`, never for an idle loop and never in free-running mode.

`frame` is the completed-step count. Store it on `OnEndFrame`, together with the ack, so a reader that sees `frame == N` is also allowed to read the engine half. The HUD therefore shows the last *completed* frame and lags the in-progress one by a single present. Do not publish `frame` from `UpdateTimeStep` to make the overlay look eager. That would let a reader observe the counter before the tick has moved the actors.

Deadlock to avoid: the tool blocks in `Recv` while `UpdateTimeStep` blocks waiting for the tool. `Recv` only polls, but the engine never reaches the drain if it is stuck in the timestep waiting for a byte the tool will not write until the reply arrives. `UpdateTimeStep` waits only for its own short sleep. The tool waits only for `STEP_ACK`.

`uectl step` sequence, after `ue_ready`:

1. `SPAWN` 1000 at spacing 100, as `demo` does.
2. Write `100.f` at `tool_bulk_off`.
3. Send `--count` steps of `--dt` (acceptance values: `0.1` and `10`). After each ack, check `frame` and `speed`.
4. `DUMP`. Check `x` within 0.01 of `i * 100 + count * speed * dt`, and `y == z == 0`.
5. `QUIT`, then the usual 60 s wait for exit code 0.

Print `stepped <count>`. Exit nonzero on the same failures as `demo`, plus a bad `frame`, a bad `speed`, or a bad position.

`ping` and `exec` while `--sync` is set must still get their replies: the idle drain pops them without a `STEP`. Do not require a step to service `PING`.

## Step 4 — window and HUD

Feasible in this milestone, with a C++ HUD and no project content. Not feasible as a free-running camera tour, a UMG layout, or a second process drawing into the same window.

`--window` is a flag on every subcommand. It drops `-nullrhi` and leaves the rest of the launch line. Combined with `step`, that is the interactive run. Combined with `launch`, the window shows an idle world and the HUD until the process exits; nothing steps, because the tool is not sending `STEP`.

Also pass, on every launch, an exec or a project ini setting that forces `t.IdleWhenNotForeground 0`.

`-unattended` stays for the first windowed run. If the window is suppressed or never focused, drop `-unattended` for `--window` only and record which one worked in `docs/tool.md`. Do not drop it for headless.

HUD implementation:

- A `UCLASS` `AHUD` in the plugin. No UMG module, no widget asset, no Slate viewport overlay.
- On the first ready tick, `ClientSetHUD` on the world's first player controller. `/Engine/Maps/Entry` already starts a game world with one. If `GetFirstPlayerController()` is null, log and retry next tick; do not spin.
- `DrawHUD` uses `UCanvas` and `GEngine->GetSmallFont()`.
- Lines, all read on the game thread: `state`, both heartbeats, `flags`, `frame`, the last `STEP` dt, two rates, and the eight most recent commands.
- Rates. Render rate is the recent average of `1 / FApp::GetDeltaTime()` over frames whose delta is greater than 0. Sim rate is `1 / dt` of the last accepted `STEP`, and 0 if no step has completed. Label them so a 0-delta idle loop is not presented as the simulation rate.
- The eight-line transcript lives in plugin memory. The rings do not keep history after a pop. Each line is the type, the id, and a short result (`ok`, `spawned`, `frame`, `err`). The header mirror (`last_cmd_*`, `last_rsp_*`) is what counts as shared-memory state; the transcript is local context under it.
- In `--window` only, set the engine cube `/Engine/BasicShapes/Cube` on each spawned mesh and set that component movable before `SetActorLocation`. Headless spawns stay mesh-less, so `demo` does not start loading render meshes under `-nullrhi`.

The window is a view of the lockstep, not a second simulator. While the tool is between steps, the picture is still. When a step is applied, the cubes jump by `speed * dt` and the frame line increments. That is the behavior to demonstrate.

Out of scope for step 4: player movement, mouse look, UMG, Slate widgets, editing the keynote, and any claim that Chaos steps deterministically. Actor motion is the explicit `SetActorLocation` in the step handler.

## Tests and runs

CMake tests stay `shm_two_process`, `ring_empty`, `ring_full`, `ring_wrap`, `ring_stress`. They do not launch the engine. CI stays that way.

After the protocol change, rebuild the plugin before any engine command, and clear a stale `UnrealEditor.modules` if the dylib suffix moved.

Manual acceptance, from the repo root, engine `/Users/migueldovale/Epic Games/UE_5.8`, project `/Users/migueldovale/Work-local/ueshm/project/ueshm.uproject`:

```
cmake -S . -B build && cmake --build build && ctest --test-dir build
./build/uectl demo --engine "/Users/migueldovale/Epic Games/UE_5.8" --project "/Users/migueldovale/Work-local/ueshm/project/ueshm.uproject"
./build/uectl step --dt 0.1 --count 10 --engine "/Users/migueldovale/Epic Games/UE_5.8" --project "/Users/migueldovale/Work-local/ueshm/project/ueshm.uproject"
./build/uectl step --dt 0.1 --count 10 --window --engine "/Users/migueldovale/Epic Games/UE_5.8" --project "/Users/migueldovale/Work-local/ueshm/project/ueshm.uproject"
```

`demo` prints `spawned 1000` and exits 0. Headless `step` prints `stepped 10` and exits 0. Windowed `step` does the same, and during the run the window shows the cubes and a HUD whose frame line reaches 10. The engine log still contains `ueshm ready`.

## Do not

- Block in `UpdateTimeStep` until the tool writes.
- Pop the command ring from both the ticker and the timestep.
- Write both processes into one bulk span.
- Change `demo`'s spawn count, spacing, or position check.
- Turn on sync for `demo`.
- Add UMG, a content plugin, or a mesh on the headless spawn path.
- Treat render FPS and step rate as the same number.
